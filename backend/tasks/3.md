## Key context

sqlc copies the comment lines directly above a `-- name:` line into the generated Go as a doc
comment, and a comment placed before the first query lands inside the SQL constant. That is
why your editor note shows up in `users.sql.go`. Generated code should contain only what the
SQL file means.

With a join, `SELECT *` returns every column from both tables, and both tables have `id` and
`created_at`. Look at how sqlc handles duplicate names, then decide whether to select columns
explicitly with aliases or use sqlc's embed feature. Read what each choice generates and pick
the one that gives your service layer the cleanest struct.

"Valid" depends on time. Decide whether the database or Go supplies the current time, and
note that this choice decides whether the query is easy to test later. For Phase 1 the
simpler option is fine, but make the choice on purpose.

Ownership matters because a token hash alone proves nothing about who is asking. A delete
that ignores the user lets one user's request remove another user's session if a hash leaks.
